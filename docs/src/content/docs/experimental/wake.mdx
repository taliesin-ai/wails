<Aside type="caution" title="Retired switch">
The `WAILS_USE_WAKE` variable has been removed and is ignored. Use
`WAILS_EXP_USE_WAKE` to opt in (see below).
</Aside>

Wake is the name of Wails' new build system. It reads a single `wails.yaml`
manifest, plans every step of a build before it runs, and caches the results.
It replaces the generated Taskfiles that current projects use, so you do not
write Taskfile tasks to build, package or sign your app.

Taskfiles remain the default. Nothing changes for an existing project until you
set `WAILS_EXP_USE_WAKE` and activate a `wails.yaml`.

## What wake does

- **Plans before it runs.** `wails3 build --plan` prints every stage, target and
  output path without touching the disk. `--json` gives the same plan in a
  versioned, machine-readable form.
- **Validates configuration.** `wails3 config check` checks `wails.yaml` and
  every named profile without building anything. Errors point at the field and
  the source line.
- **Builds only what changed.** Steps declare their inputs, so an unchanged
  build is served from the cache. `wails3 build --force` ignores cache entries.
- **Keeps your files.** Wake copies the files it needs into a disposable
  `.wails/` workspace. It never edits your icons, plists, package templates or
  scripts.

## Enabling wake

Set `WAILS_EXP_USE_WAKE` in the shell that runs `wails3`. The variable is
presence-based: any value, including an empty one, turns it on.

```bash
export WAILS_EXP_USE_WAKE=1     # Bash or Zsh
```

```powershell
$env:WAILS_EXP_USE_WAKE = '1'   # PowerShell
```

Unset the variable to go back to Taskfile routing. With it unset, the
`migrate`, `config`, `eject` and YAML-only commands are not available.

The full walkthrough for a new `wails.yaml` project is in
[YAML builds](/experimental/yaml-builds). If you already have a Taskfile
project, read [Moving from Taskfiles to wake](/experimental/taskfile-to-wake)
for the migration steps and the command mapping.

## Where Taskfiles fit

Taskfile projects still build through the embedded Task runtime. `wails3 task`
runs your Taskfile tasks, and the generated `build/` Taskfiles keep working
exactly as before. `WAILS_EXP_USE_WAKE` does not change how a Taskfile project
builds.

Wake contains an internal executor for Taskfile syntax. It is not a supported
way to run Taskfiles, and it is not selected by `WAILS_EXP_USE_WAKE`. Its
options and environment variables are not a public interface, so this page does
not document them.

## Feedback

Wake is experimental, and feedback decides what happens next. If you try it,
tell us what you ran, what you expected and what happened in the
[Wake feedback discussion](https://github.com/wailsapp/wails/discussions/5679).
